# IWO_PHYSICS_CONSTRAINED_MODEL_V1

One thickness-aware Silvaco ATLAS material model for ~2 % W-doped In2O3 (IWO) thin-film transistors, M(t, xW) -> ATLAS -> ID-VG, calibrated against the measured transfer curves of the 2.0, 6.3, 13.2 and 31.8 nm devices (VD = 0.7 V). Built 2026-09-20/21 on the local licensed installation (DeckBuild 5.0.10.R, ATLAS 5.28.1.R, C:\sedatools). Every simulated number in this package comes from a real ATLAS launch recorded in `results/RUN_INDEX.csv`; every material number carries a provenance label (`tables/PARAMETER_PROVENANCE.csv`).

Read in this order: `FINAL_STATUS.md` (what is done, what is not, publication-readiness) -> `docs/SUPERVISOR_SUMMARY.md` -> `tables/EXPERIMENTAL_VS_SIMULATION.md` -> `tables/MATERIAL_PARAMETERS_USED.md` -> `docs/PHYSICS_MODEL.md` -> `docs/LIMITATIONS.md`.

## Reproduce

Python: the virtual environment of the sibling Claude package (`..\IWO_ATLAS_Model_claude\.venv\Scripts\python.exe`, numpy/scipy/matplotlib/pyyaml/openpyxl). All commands from this directory.

```
python scripts/material_laws.py                       # laws -> config/iwo_material_model.yaml, tables/THICKNESS_LAWS.csv
python scripts/build_iwo_decks.py --thickness 2       # deck only (no launch)
python scripts/run_atlas.py --thickness 2 --label test --override traps.fixed_interface_charge_Qf_cm2.value=1.73e12
python scripts/compare_experiment_simulation.py       # from results/BEST_RUNS_V1.json
python scripts/plot_results.py
python scripts/make_provenance_tables.py
python scripts/sensitivity_analysis.py --thickness 2 --cases chi_m0p1 nd_x2 --stride 2
```

`run_atlas.py` refuses to launch beyond `solver.yaml: runner.max_launches`; each launch is a fresh directory and is never overwritten.

## Final deck form (user directive, 2026-09-21)

The final runs (2 nm and 13.2 nm calibrated; 6.3 nm validation with the shared parameters, run_0014; 6.3 nm tuned with one device-specific flat-band offset and its own band mobility, run_0015) use the PHYSICAL structure and the STEPPED sweep, both now the defaults in `config/geometry.yaml` (`structure: full`) and `config/solver.yaml` (`sweep.mode: stepped`):

- regions: IWO channel (two regions, the 0.25 nm one carries the interface DOS), Al2O3 2 nm, HfO2 15 nm (permittivities 9.0 / 19.57 set explicitly), Conductor volume 50 nm for the TiN gate (TiN is not in the ATLAS metal table; work function 4.70 eV on CONTACT), Air 70 nm above the channel, Pd source/drain volumes 70 nm x 2 um on the IWO top surface (no CONTACT work function -> Ohmic, ASSUMED);
- bias: `solve vstep=-0.1 vfinal=-3 name=gate`, `solve vstep=0.1 vfinal=0.7 name=drain`, then logged blocks `solve vgate=-3 vstep=0.2 vfinal=-1 name=gate`, `solve vstep=0.05 vfinal=<Vth> name=gate` (strict acceptance up to the measured Vth, then default), `... vfinal=1.5`, `solve vstep=0.1 vfinal=3 name=gate`: 76 solved points, scored against the measured points on the same grid.

Runs 0001-0009 (calibration stages) used the reduced boundary deck and one SOLVE per 0.05 V point; run_0012 vs run_0008 (identical parameters) is the equivalence check between the two forms. The 31.8 nm device was excluded from the final set by the user (its runs 0006 and 0010 are kept as evidence).

## Conventions

- Currents are A per um of width (simulated width 1 um). The measured data were divided by W = 290 um exactly once (`data/data_summary.json`). Never divide again.
- "2 % W" is a composition label, not an electrically active donor density.
- Native zero currents from the solver are reported as zeros (counted), never floored.
- NOT DETERMINED FROM AVAILABLE DATA marks every quantity the supplied inputs cannot fix.
